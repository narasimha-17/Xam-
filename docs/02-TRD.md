# Document 02 — Technical Requirements Document (TRD)

## Frontend
React 19 + TypeScript, built with Vite. Tailwind CSS v4 (CSS-first config via `@tailwindcss/vite`, no `tailwind.config.js`). No Next.js — this is a plain SPA served by Vite in dev, static build for production.

## Backend
FastAPI (Python 3.12), running under Uvicorn. Async throughout (`async def` routes, async SQLAlchemy sessions).

## Database
PostgreSQL, accessed via SQLAlchemy 2.0 (async engine, `asyncpg` driver for the app; `psycopg2` used only as the sync driver for Alembic migrations). Schema managed with Alembic (one autogenerated migration covers the full initial schema).

## Auth
Custom JWT auth (not a third-party provider): `python-jose` for token encode/decode, `passlib[bcrypt]` for password hashing. `OAuth2PasswordBearer` + `OAuth2PasswordRequestForm` on the FastAPI side (so `/docs` Swagger UI's "Authorize" button works out of the box); the frontend posts `application/x-www-form-urlencoded` to `/auth/login` to match. Tokens are stored in `localStorage` on the client and attached via an axios request interceptor.

## Hosting
Not yet deployed — currently local-only. `docker-compose.yml` exists (Postgres + backend + frontend containers) for when deployment is needed, but the primary dev workflow in this build used a native local PostgreSQL 18 install directly (Docker Desktop's engine wasn't running in the dev environment), with the backend running via a Python venv and `uvicorn --reload`, and the frontend via `npm run dev`.

## Third-Party APIs
**JDoodle Compiler API** (`api.jdoodle.com/v1/execute`) — executes student-submitted code for coding-type exam questions (Python, Java, C++). Chosen after two other options fell through: Piston's public API now requires manual whitelist approval (as of Feb 2026), and self-hosting Piston/Judge0 via Docker wasn't viable since Docker Desktop's engine wasn't running in this dev environment. Free tier: ~200 executions/day. Credentials (`JDOODLE_CLIENT_ID`, `JDOODLE_CLIENT_SECRET`) are required in `backend/.env` — without them, the run/submit endpoints degrade gracefully (return a clear "not configured" error per test case) rather than crashing.

## Key Libraries
**Backend**: `fastapi`, `uvicorn[standard]`, `sqlalchemy`, `asyncpg`, `psycopg2-binary`, `alembic`, `pydantic` v2, `pydantic-settings`, `python-jose[cryptography]`, `passlib[bcrypt]` + pinned `bcrypt==4.0.1` (newer bcrypt breaks passlib 1.7.4's version probe), `python-multipart` (file uploads), `email-validator`, `httpx` (async HTTP client, used to call the JDoodle API).

**Frontend**: `react-router-dom` (client-side routing), `@tanstack/react-query` (server state/caching), `axios` (HTTP client), `react-hook-form` (forms, including nested `useFieldArray` for the exam builder), `framer-motion` (page/element transitions, modal animation), `lucide-react` (icon set), `clsx` + `tailwind-merge` (the `cn()` className helper), `@tailwindcss/vite`.

## Environment Variables
**Backend** (`backend/.env`, from `.env.example`):
`DATABASE_URL`, `SYNC_DATABASE_URL` (async/sync Postgres URLs), `JWT_SECRET_KEY`, `JWT_ALGORITHM`, `ACCESS_TOKEN_EXPIRE_MINUTES`, `UPLOAD_DIR`, `CORS_ORIGINS`, `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD`, `SEED_ADMIN_NAME`, `JDOODLE_CLIENT_ID`, `JDOODLE_CLIENT_SECRET`.

**Frontend** (`frontend/.env`):
`VITE_API_URL` (defaults to `http://localhost:8000` if unset).

## Constraints / Preferences Locked In During Build
- PDFs served through an **authenticated download endpoint**, not raw static file hosting — enforces login before any file is served, and lets the client fetch as a blob (via the JWT header) rather than putting a token in a URL query string.
- Grading is always computed **server-side on submit**; correct answers are withheld from the exam-detail response until after submission.
- Progress stats are **computed on read** from `exam_attempts`/`attempt_answers` rather than stored redundantly, to avoid a second source of truth.
- Bcrypt must be pinned to `4.0.1` alongside `passlib==1.7.4` — newer bcrypt versions break passlib's internal version check.
- Tailwind is v4 (CSS-first `@theme` block in `index.css` + `@tailwindcss/vite` plugin), not the v3 `tailwind.config.js` pattern — this was a build-time correction after `npm install tailwindcss` pulled latest v4 by default.
- Coding questions grade by **stdin/stdout comparison** (trimmed exact match), not function-signature harnesses — this keeps grading uniform across Python/Java/C++ without generating per-language wrapper code. Admin-authored starter code must itself read stdin and print to stdout (Java starter code must define `public class Main`).
- JDoodle's `versionIndex` per language (`app/services/jdoodle.py`) was set from commonly documented values and confirmed working for Python/Java/C++ at build time — if JDoodle changes its installed runtime list, these may need bumping.
- The full coding grading result (`test_case_results`, pass/fail per case) is persisted on `attempt_answers.graded_detail` at submit time rather than recomputed on every results-page view — re-running against JDoodle on each view would burn through the free tier's ~200/day quota needlessly.
